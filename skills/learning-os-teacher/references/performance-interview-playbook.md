# Performance and interview playbook

Use this reference only when the current Learning OS-selected episode is interview/mock, explicitly fluency-oriented, or benefits from realistic performance conditions and debrief. Do not use it to create a separate interview curriculum or mastery model.

## Contents

- Invocation rule
- Fluent execution versus deliberate learning
- Reflection deferral
- Authentic artifacts
- Contrastive benchmark feedback
- Interview-signal feedback
- Performance pressure without fake difficulty
- Stop rules

## Invocation rule

Preserve uninterrupted performance when interruption would invalidate the skill being measured. Teaching and reflection can happen afterward. The delivery context and existing evidence lifecycle remain authoritative.

## Fluent execution versus deliberate learning

During deliberate learning, brief reflection inside the episode may help build the model.

During fluent execution, especially interview/mock:

```text
present task
-> learner performs without coaching
-> collect observable work
-> assess
-> debrief afterward
```

Do not interrupt a competent learner every step with "why?" merely because metacognition is usually useful. Fluency itself can be the performance target.

This is a teacher execution posture, not durable `automaticity` state.

## Reflection deferral

Defer answer-bearing explanation and metacognitive analysis until the attempt closes when mid-attempt reflection would contaminate the signal.

Useful debrief questions include:

- Where did your reasoning become uncertain?
- Which assumption drove the key decision?
- What evidence would have changed your approach?
- What would you say more concisely next time?

Do not retrofit debrief quality into technical correctness or mastery state.

## Authentic artifacts

When compatible with the selected intent, prefer realistic surfaces over artificial prose. This includes an **authentic bridge**: give the learner a realistic artifact with a small amount of unfamiliar-but-inferable detail and ask for the governing mechanism or gist rather than requiring exhaustive comprehension.

Prefer surfaces such as:

- code fragments;
- logs and traces;
- SQL/query plans;
- API contracts;
- diffs/PR snippets;
- metrics dashboards or textual metric summaries;
- architecture constraints;
- incident/failure descriptions.

Use only enough realism to exercise the selected objective. Do not add noise merely to simulate seniority.

## Contrastive benchmark feedback

After the learner's untouched response has been assessed, a compact reference answer can help when the delta is more useful than another question.

Compare:

```text
learner response
vs
concise strong reference
```

Focus on the delta:

- missing causal link;
- unnecessary branch;
- stronger ordering;
- overlooked invariant/trade-off;
- terminology that obscures otherwise-correct reasoning.

A model/reference answer is teaching exposure when it supplies target reasoning. It never retroactively upgrades the original attempt.

## Interview-signal feedback

Keep technical evidence separate from descriptive interview signals.

Useful observable signals include:

- clarifying assumptions;
- state ownership and invariants;
- causal reasoning;
- trade-off prioritization;
- capacity/backpressure awareness;
- failure/recovery thinking;
- observability;
- precise uncertainty;
- concise answer structure.

Signal feedback is coaching only. Do not let it mutate correctness, readiness, weaknesses, review timing, transfer, durability, or FSRS.

## Performance pressure without fake difficulty

Realistic performance can include bounded time, incomplete information, or a noisy artifact when the selected context actually calls for it. Do not make every practice task compound/noisy.

Prefer the smallest realistic pressure that tests the intended capability. If the learner explicitly asks for easier chunking during ordinary practice, adapt. During interview/mock, neutral clarification is allowed but answer-structuring decomposition is a hint and may invalidate a clean signal.

## Stop rules

Stop when:

- the selected performance task is complete;
- enough evidence exists for the frozen criteria;
- debrief has identified the highest-value correction;
- further questioning would become coaching rather than assessment;
- the learner did not request a deeper interview-analysis session.

Do not turn every interview answer into a full lecture, rubric dump, or communication audit.
