# SCAMPER

Use this method only when there is one existing idea, product, artifact, or process to transform. Do not use it for blank-page ideation.

## Workflow

1. Confirm the existing idea and which parts are fixed versus open to change.
2. Run all seven operations in order:
   - Substitute
   - Combine
   - Adapt
   - Modify or Magnify
   - Put to other use
   - Eliminate
   - Reverse or Rearrange
3. For each operation, choose 3-4 questions from the bank below that genuinely bite. Answer only those. Mark an operation empty if nothing useful emerges.
4. Deduplicate variants across operations. The same change counts once even if two lenses discover it.
5. Convert the hits into named variants. State for each:
   - what changes
   - what it costs
   - what it risks
6. Scan which operations produced hits and which were dry. Treat that concentration as a diagnostic of where the current idea is soft or overbuilt.
7. Rank the variants, call out weak ones, and offer to deepen one, rerun one operation harder, switch technique, or stop.

## Question bank

### Substitute

- What if a different actor performed this step?
- What if the default were the opposite?
- What if the unit of work were larger or smaller?
- What if a built-in replaced a dependency, or vice versa?
- What if the input medium changed: voice, image, text, gesture?

### Combine

- Which two steps could become one action?
- Which adjacent feature could merge into this one?
- Could setup and first use become the same moment?
- Could two user roles share one interface?

### Adapt

- How does a distant industry solve this shape of problem?
- What familiar convention could be adopted wholesale?
- What offline or older version of this workflow had a useful mechanism?
- What game, logistics, or natural-system pattern maps here?

### Modify or Magnify

- What if this were ten times larger or one hundred times smaller?
- What if it were much faster or deliberately slower?
- What if the frequency became once ever, once daily, or continuous?
- What if one use case became the entire product?

### Put to other use

- Who outside the intended audience could use this as-is?
- What by-product could become the primary value?
- Could its data power a different capability?
- What adjacent job could it solve with no implementation change?

### Eliminate

- Which step can disappear rather than be improved?
- What configuration exists only because nobody chose a default?
- Could the account, login, wait, confirmation, or mode disappear?
- What is the smallest version that still delivers the core value?

### Reverse or Rearrange

- What if the last step happened first?
- What if the system asked instead of the user?
- What if sender and receiver, author and reviewer, or client and server swapped roles?
- What if delivery happened before configuration?

## Honesty mechanics

Expect only about 3-5 of the seven operations to produce meaningful hits. Show empty lenses instead of padding them.

An operation with no new variant is still evidence. A run where all seven work cleanly is suspect.

## Prohibitions

- Do not transform a vague or nonexistent starting idea.
- Do not answer every question merely because it exists in the bank.
- Do not disguise one variant under multiple operation names.
- Do not invent variants to fill empty lenses.
